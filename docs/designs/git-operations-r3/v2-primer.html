拉取变更 chip options

合并方式做成胶囊 chip，解释表沿用四行结构。

↓拉取变更✕
git pull origin main⧉
--rebase--ff-only--no-ff--squash --no-commit--no-verify
Intent
先从 origin 拉取 main，再把本地新增提交接到远端最新提交后面。
Will happen
本地提交重新接到远端之后，记录更整齐；冲突时暂停等你处理。
Will NOT
不会创建合并提交，也不会推送；rebase 后本地 hash 可能变化。
Example
git pull --rebase origin main

获取远端更新 minimal

无参数操作：一个 hero 行 + 后果表。

⇓获取远端更新✕
fetch → all remotes仅更新远端引用元数据
Intent
更新远端引用信息用于比对。
Will happen
将以默认作用域 all remotes 执行 fetch。
Will NOT
不会把变更合并到当前分支。
Example
git fetch --all
