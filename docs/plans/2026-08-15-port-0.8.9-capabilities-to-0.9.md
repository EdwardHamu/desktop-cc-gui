## 0. 先回答合理性

把 62 个 0.8.9 commit 原样搬进 0.9 **不合理**。原因不是「工作量大」，是三类东西被混在一起了：

| 类型 | 含义 | 默认动作 |
|---|---|---|
| **0.9 上仍在的缺陷** | 分叉后 0.9 没改这条路径，或改了骨架但缺陷合同还在 | 按 0.9 写法修，带走 0.8.9 测试 |
| **0.9 已用另一条路消掉** | 同一用户症状，0.9 解法不同（有时更好） | **不搬 0.8.9 补丁**，只记「已覆盖」 |
| **0.8.9 自己新功能的回归** | 0.9 从未上船的能力（PI / Index-only 侧栏 / 内嵌 Dock）上修出来的 bug | **不单独修**；只有决定移植该功能时，才作为该功能的验收项 |

0.8.9 里很大一块（engine rail 还原、Index replace 盖引擎、PI `@` 断链、Shared PI 白名单、Dock 右键隔离）属于第三类。把它们当成「0.9 用户正在疼的 bug」是错的。

正确策略仍是：**能力簇 + 测试/行为当合同**。但每一簇开工前必须先过「0.9 现状判定」。下面逐条给判定。

## 1. 判定口径（四态）

每个条目只标一个主状态：

- `STILL` — 0.9 同源路径上缺陷仍在，用户可复现
- `TRANSFORMED` — 0.9 重写了路径，旧补丁对不上；症状可能还在，必须按新路径重写
- `SUPERSEDED` — 0.9 已用别的实现覆盖，再搬 0.8.9 会重复或回退
- `N/A-UNTIL-FEATURE` — 只在 0.8.9 新功能里存在；0.9 没这功能就没有这个 bug
- `FEATURE` — 不是修缺陷，是产品增量，要单独拍板
- `VERIFY` — 代码像有问题，但 0.9 可能已用 8MB 栈 / 渲染窗等压住；先复现再写

## 3. 仍成立的缺陷：写法与 0.9 落点

### B1 Windows 打开方式黑窗 — `STILL`

**0.8.9 合同：** `openspec/specs/open-app-target-detection/spec.md`。探测/图标提取走 `std_command`（`CREATE_NO_WINDOW`）。`CODEMOSS_SHOW_CONSOLE=1` 仍可恢复窗口。返回字段语义不变。

**写法：** 只改两处启动子进程，不要动 Explorer 打开（0.9 `:2446` 明确 Explorer 禁止 `std_command`）。

**0.9 落点：** `src-tauri/src/workspaces/commands.rs` `get_open_app_icon` / `command_resolvable_on_path`。

**复用：** 可以无损两行。不碰 AppShell。

### A1 超时余量 — `STILL`

**合同：** 单一常量 `ASK_USER_QUESTION_TIMEOUT_SECS = 1800`；`MCP_TOOL_TIMEOUT_MS = (1800 + 30) * 1000 = 1_830_000`。固定 30s，不用百分比。`build_command_raises_mcp_tool_timeout_when_ask_wired` 断言从 `1800000` 改为 `1830000`。

**0.9：** `claude.rs` 写死字符串 `"1800000"`；`user_input.rs` 两处 `from_secs(1800)`；`tests_stream.rs` 仍断言 1800s。

**复用：** 纯 Rust 常量提取，可复用算法。0.9 文件还在。

### A2 + A3 过期答案 + 墙上时钟 — `STILL`

**0.8.9 写法：**

1. 后端：`ask-*` + 该 workspace 有 Claude session + 是 user-input 响应 + 无 pending → `AskUserQuestion request {id} already expired or was answered`。三条件缺一不可（无 Claude 的 workspace 仍走连通性错误；approval 不得误伤）。
2. 前端分类器无条件认这句，**不**依赖 `staleSettlementHint`。
3. stale 先 tombstone 再摘卡（0.9 已有 tombstone 路径，差的是进得去）。
4. UI deadline = `Date.now()` 锚定，读取时重算。测试：`vi.setSystemTime` 且 **不** `advanceTimersByTime`。

**0.9：** 分类器有 `unknown request_id for askuserquestion`，但没有 expired 句；`workspace not connected` 必须搭 `staleSettlementHint === "timeout"`。后端仍把晚到 ask 掉进 Codex fallback。倒计时仍 tick-1。

**复用：** `expired_claude_ask_request_id` 纯函数可原样搬。分类器加一句。倒计时重写组件内 state，不碰 AppShell。

### A4 闸门前丢字 — `TRANSFORMED`（0.9 上仍会发生）

**0.8.9 合同测试：** `useThreadEventHandlers.test.ts` — channel 里先有壳 delta + tail，`onRequestUserInput` 后 tail 必须以 `appendAgentDelta` **先于** gate settle。

**0.8.9 写法：** `settleThreadWaitingForUserChoice(threadId, workspaceId)` 里：

```text
flushPendingRealtimeEvents()
drainLiveAssistantTextTail(threadId) → appendAgentDelta
然后 markProcessing(false) + settleThreadPlanInProgress
```

只 drain 不 flush：assistant item 还不在时 `appendAgentDelta` 会另开一条，尾部跑到问题卡后面。

**0.9：** 同名函数只有三行 settle，零 drain。但 0.9 还有 `liveItemDeltaChannel` / `flushLiveAssistantShadowTranscriptsNow`。T4 **禁止**贴 0.8.9 hunk，必须接到：

- live assistant text channel（正文）
- live item delta（reasoning/tool，0.9 新增）
- 现有 `flushPendingRealtimeEvents`（turn completed 等边界已经在用，`:1284` `:2449`）

闸门结算要和「turn completed / error / stalled」同一套 flush-then-drain。

### A5 选中勾 — `STILL`

纯 CSS + `UserInputQuestionCard` 一个 check span。token：`--text-accent`。0.9 只有底色。可复用 0.8.9 样式，几乎无冲突。

### D1 工具输出预算 — `STILL`

**合同：** `boundToolOutput.test.ts`。`commandExecution` 256KiB（64KiB 头+尾）；`fileChange` 1MiB（128KiB 头）。`…[omitted N chars]…`。`ccgui.perf.toolOutputBudget=off` 回退。日常小 diff 不丢。事件不丢，截断在组装层。

**0.9：** `NO_TRUNCATE_TOOL_TYPES` 仍豁免；`appendToolOutputDelta` 无界拼接。live channel **不**救 store：settle 仍把全文放进 `items`。32GB 场景在 0.9 一样成立。

**复用：** `boundToolOutput.ts` 纯函数原样。接线：`normalizeItem` / append / history hydrate。`.codexignore` 托管段是附带防护，可同 PR 或拆 T6b。`c63942451` 越界切片必须一起带（6 行防御）。

### E1 协作弹层裸样式 — `STILL`

**0.9 根因：** `bootstrap.ts:21-23` 把 `multi-agent.css` 赶出首屏；`ComposerToggle` 仍渲染 `ma-collab-pop`，却不 load。0.8.9 的修法就是 Toggle 自己 `useFeatureStylesReady(loadSubagentStyles)`，弹层等 `stylesReady`。

**不要**把 `multi-agent.css` 塞回 bootstrap（破坏 0.9 冷启动）。

### E2 Diff 滚动 — `VERIFY` 偏 `STILL`

0.8.9 合同测试要：viewer 明确高度 `min(72vh)` + unified 滚 `.diff-viewer` + split 只滚 `.cm-scroller`。0.9 注释仍采用「短 diff hug content」。0.8.9 说这条已手测裁掉单栏滚动。

### H1 打开历史录像回放 — `STILL`（0.9 渲染窗救不了）

**两层不要混：**

| 层 | 0.8.9 | 0.9 |
|---|---|---|
| 渲染窗 | 后来也做了 chip | `messagesHistoryWindow` 已有，只裁 `renderedItems` |
| hydrate 方向 | tail-first + prepend | **仍 prefix** `slice(0, 80/160/…)` |
| 磁盘 IO | `load_*` 支持 limit/before | `load_claude_session` **无**窗口参数，一次全文 |

**写法：** 改 `dispatchThreadItemsProgressively` 为先 `slice(-N)`，再向上 prepend；短列表一次 set。`pendingOlderHistory` 纯模块可复用。磁盘窗口化是 H1 的加强（T9b），可第二刀。

**重写点：** `useThreadActionsResumeThread.ts`（0.9 S4 后热路径）。禁止 cherry-pick。

### O1 会话管理默认全扫 — `STILL`

**0.8.9：** `query_requires_exhaustive_scan` 只认显式 `scan_mode=exhaustive`。设置页默认 Bounded；「扫描全部」二次确认。

**0.9：** keyword / folder / archived **隐式** Exhaustive。空列表打开已是 Bounded（这点 0.9 已经对）。用户一搜索就打回全盘。

**复用：** Rust 函数可搬。前端「扫描全部」按钮是产品面，一起做。

### G1 终端组自动折 — `STILL`

小组件本地 state：mount 时若已无 processing → 默认折；processing→空 → 折并清 `expandedItemId`。0.9 时间线有 process-phase 折叠，但 **组组件自己默认展开**，直播收尾仍占高。不进 reducer。

## 6. Review：这么做站不站得住

### 站得住的部分

1. **先问「0.9 还是不是 bug」** 避免把 0.8.9 的自产回归（rail、PI `@`、Index replace）当成 0.9 待办。那会浪费一周去修一艘 0.9 没开的船。
2. **H1 与 H0 分层** 纠正了上一版最危险的误判：0.9 有 chip ≠ 打开不再录像回放。`slice(0, n)` 还在，这是用户能感到的。
3. **A4 标 TRANSFORMED** 避免把旧 `useThreadEventHandlers` 贴进已拆 live delta 的 0.9，造成静默丢字或打穿根链。
4. **E3 SUPERSEDED** 避免「修复延迟 CSS」把 0.9 已经放回 bootstrap 的 composer 样式再拆出去。
5. **Wave 1 可验证**：每个 STILL 都能指到 0.9 行号。不是印象。

### 仍有的风险 / 我可能错的地方

1. **C1 Box::pin。** 0.8.9 炸栈时 Windows 还是 1MB。0.9 已 8MB。再搬五处 pin 是防御，不是已证实的现网崩溃。没 repro 就做，属于过度。
2. **E2 Diff。** 0.9 可能在别的选择器上修过滚动。必须手测后再改，否则短 diff hug 是 0.9 有意 UX。
3. **G1 vs 时间线折叠。** 过程阶段折叠之后，组组件自动折的收益变小。仍建议做：直播收尾、组默认展开，时间线折叠管不到组内部。
4. **T9 和 0.9 渲染窗叠在一起。** tail-first hydrate + 渲染窗同时存在是对的（IO/commit 一层，DOM 一层），但两层窗口数字不要各发明一套。T9 应复用 `HISTORY_WINDOW_SIZE` 或明确「hydrate 首包 = 渲染窗」。
5. **F4 Index 仍可能是错优先级。** 0.9 侧栏已经 5 条 first-paint。用户在 0.8.9 感到的「列表又慢又先错后对」，0.9 可能已经可接受。没在 0.9 上录一条「侧栏仍错」的视频就开 F4，是架构瘾。
6. **文档上一版的簇级 Wave 把 FEATURE 和 STILL 捆在一起**，会让人以为「要先把 0.8.9 全部能力搬完 0.9 才完整」。这版把它们拆开。0.9 可以只收 Wave 1 就发版。

### 对「以能力簇为 PR」的修正

能力簇仍是 FEATURE 的正确单位（PI、Dock、Index）。  
**缺陷不是。** A1–A5 虽都叫 AskUserQuestion，T2（常量）和 T4（live channel 边界）冲突面差一个数量级，捆成一个 PR 会让小修被热路径 review 拖死。

所以：

- **缺陷：一个症状一个 PR**（上表 T*）
- **功能：一个能力簇一个 PR**（上表 F*）
- **合同：测试和行为，不是 diff**
- **复用：纯函数 / 纯 Rust 小修可以抄；`app-shell` / `useThread*` / `Messages*` / resume 默认重写**
